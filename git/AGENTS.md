# Repository Location

Before starting a git-related task, check whether the target repository is already cloned under `~/git`. Reuse the existing clone when it is present. When it is not, clone it into `~/git` and work there. Do not clone into any other directory.

# Updating Before Working

Run `git pull` in the target repository before making any change, and check out the default branch first when the clone is on a stale feature branch. The remote often carries commits that are not in the local clone, and building on an outdated base means the work has to be rebased or reapplied later.

# Python Lockfiles

Run `uv lock` with an empty user-level configuration, for example `XDG_CONFIG_HOME=$(mktemp -d /tmp/uvcfg.XXXXXX) uv lock`. Otherwise the `exclude-newer` settings in the user's `uv.toml` are written into `uv.lock`, and `uv sync --locked` in CI, which lacks them, rejects the lockfile as stale.

# GitHub Configuration

Keep `.github` consistent across the `rewse/*` repositories cloned here. A repository may differ only for a reason stated in this section or in its own AGENTS.md. Repositories hosted on GitLab and forks of upstream projects are out of scope.

- Give every repository a `.github/dependabot.yml` that covers `github-actions` and each package ecosystem it uses (`docker`, `npm`, `pre-commit`, `uv`). Each entry runs weekly (the `docker` entry in `rewse/actions` runs daily, because its TruffleHog image updates are released to every repository), groups all updates of the ecosystem into one pull request, and sets `cooldown.default-days: 5`, because Dependabot counts whole days and 4 can admit a release about 80 hours after publication, short of the 96-hour minimum package age. Exempt `rewse/*` from the cooldown in the `github-actions` entry, since those are our own actions. zizmor asks for at least 7 days, so end each `default-days: 5` line with `# zizmor: ignore[dependabot-cooldown]` and the reason instead of raising the value.
- Enable Dependabot alerts and Dependabot security updates in every repository. Security updates open a pull request as soon as an advisory is published, regardless of the weekly schedule and the cooldown, which is what brings vulnerability fixes in quickly.
- Give every repository `dependabot-review.yml`, which calls `rewse/actions/dependabot-review`, and set it up when the repository is created: register `DEPENDABOT_APP_CLIENT_ID`, `DEPENDABOT_APP_PRIVATE_KEY`, and `KIRO_API_KEY` as Dependabot secrets with `gh secret set --app dependabot`, not as Actions secrets, because a workflow that Dependabot starts reads only Dependabot secrets, and confirm that the `rewse-dependabot-review` App is installed on the repository. The client ID and the private key file are in the 1Password item `rewse-dependabot-review`, and the Kiro API key is the `credential` of `Kiro`; pipe them from `op read` so they never reach the terminal. The review fails on every Dependabot pull request until all three exist.
- Keep Ubuntu container images on an LTS release. In the `docker` entry, ignore `version-update:semver-major` and `version-update:semver-minor` for each Ubuntu image (for example, `dependency-name: ubuntu/ubuntu`), so Dependabot still updates the digest of the current tag but never proposes an interim release such as 26.10, whose nine-month support window is too short for a base image. Move to the next LTS by hand.
- Pin every `uses:`, including reusable workflows, to a full commit SHA followed by `# vX.Y.Z`. Do not reference tags or branches, because a tag can be moved to malicious code; Dependabot keeps the pins current.
- Set top-level `permissions` to `contents: read` and grant anything more on the job that needs it.
- Set `persist-credentials: false` on `actions/checkout`, give every job a `name`, use Node.js 24 unless a dependency's `engines` rules it out, and read the Python version from `.python-version`.
- Run `gitleaks.yml` on push, pull request, and a weekly schedule, and `trufflehog.yml` as a weekly sweep, in every repository. Run the sweep through `rewse/actions/trufflehog`, which pins the TruffleHog image so that Dependabot updates it with the action. Exclude a detector (`--exclude-detectors`) or a path (`--exclude-paths`) in its `extra-args` only in a repository where it reported a false positive, and state the reason in a comment.
- Add `dependency-scan.yml` to every repository with a lockfile: install dependencies through Aikido Safe Chain and call the OSV-Scanner reusable workflow, but on pull requests call `osv-scanner-reusable-pr.yml` instead, which fails only on vulnerabilities the pull request introduces, so one already on the default branch does not block every pull request, including the one that fixes it. Pass `upload-sarif: false` in a private repository, since Code Scanning there requires GitHub Code Security.
- Give every repository a `.pre-commit-config.yaml` with the hooks for the languages it contains: actionlint, check-jsonschema, and zizmor everywhere, plus basedpyright and ruff for Python, shellcheck for shell scripts, and ansible-lint for Ansible, which match what Zed runs. Pin each `rev:` to a full commit SHA followed by `# frozen: vX.Y.Z`, set basedpyright's `typeCheckingMode = "standard"` in `pyproject.toml` or `pyrightconfig.json`, set ruff's `lint.isort` to `force-single-line = true` with `single-line-exclusions = ["collections.abc", "typing"]` to keep Google style's one import per line, and run `uvx --with pre-commit-uv==4.3.0 pre-commit@4.6.2 run --all-files` before committing.
- Run the same command in `lint.yml` after `rewse/actions/setup-safe-chain`, so the hook environments are installed through Safe Chain, and run tests in `test.yml` rather than in `dependency-scan.yml`.
- Fix lint and type findings instead of suppressing them. Suppress one only where the rule conflicts with a deliberate design or the cause lies outside the repository, and state the reason on the same line.
- Install Aikido Safe Chain with `rewse/actions/setup-safe-chain`, which takes the newest immutable release at least 96 hours old and verifies its checksum; do not pipe an installer from a branch into `sh`.
- Give each repository's scheduled workflows their own cron minutes so they do not run at the same time.
- Give every repository with a `release.yml` the tag ruleset `Protect release tags`: target `refs/tags/v*`, restrict creation, update, and deletion, and let only the repository admin role bypass it. In `rewse/actions`, the release-only App that `trufflehog-auto-tag.yml` uses may bypass it too, because that workflow tags TruffleHog image updates automatically. A tag pushed with a GitHub App token starts `release.yml`, and the dependabot-review App holds `contents: write` across the repositories, so a leaked App key could otherwise publish to npm or PyPI.
- Name a workflow file after the tool it runs or the job it does (`gitleaks.yml`, `dependency-scan.yml`, `release.yml`), use the `.yml` extension, and never rename `release.yml`, because PyPI and npm Trusted Publishing are bound to that file name.
- Keep tool configuration at the path the tool reads by default (for example, `cliff.toml` at the repository root) so it works locally without extra flags.
